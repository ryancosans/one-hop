You are a coding agent. Follow these repository rules exactly.


## One function deep

**Entry points delegate. Logic lives one call away.**

**Entry points:** HTTP handlers, CLI main, framework route handlers, `main`, anything wired into routing or the public API of a module.

### Allowed

```typescript
// Single delegation, then the response
export async function handleCreateUser(request: Request): Promise<Response> {
  const user = await createUserFromRequest(request);
  return jsonResponse(user);
}

// Sequential steps — one call per line, in order
export async function routeRequest(request: Request): Promise<Response> {
  const apiResponse = await handleApiRequest(request);
  if (apiResponse) return apiResponse;

  const staticResponse = await serveStaticFile(request);
  if (staticResponse) return staticResponse;

  return new Response("Not Found", { status: 404 });
}
```

Each called function owns the logic for that step.

### Not allowed

```typescript
// Logic inside an entry point
export async function handleCreateUser(request: Request): Promise<Response> {
  const body = await request.json();
  if (!body.email) {
    return new Response("bad request", { status: 400 });
  }
  const row = await db.insert("users", body);
  return jsonResponse(row);
}

// Nested calls on one line
return jsonResponse(parsePayload(await readBody(request)));

// Deep chains — entry calls a, a calls b, b calls c
export function handleRequest(request: Request) {
  return routeRequest(request); // routeRequest must not call another orchestrator
}
```

**Orchestrators** may sequence steps with early returns only. They must not contain business rules, parsing, or I/O beyond handing off to the next function.


### No single-line functions

Do not extract a function whose body is a single statement that reads clearer inline.

```typescript
// Bad — wrapper adds nothing
export function healthResponse(): Response {
  return new Response("ok", { headers: { "Content-Type": "text/plain" } });
}

// Good — inline at the call site
return new Response("ok", { headers: { "Content-Type": "text/plain" } });
```

A function is worth keeping when it has **multiple statements** or **real logic** (conditionals, error handling, loops).

Passthrough wrappers (`handleRequest` → `routeRequest` with no other work) are not allowed — call the target directly.

Shared helpers used in many places are fine when the body has **multiple statements** or non-trivial logic.


## When implementing changes

These apply especially to automated agents; humans benefit too.

1. **Minimize scope** — Smallest correct diff. Do not touch unrelated code.
2. **Avoid over-engineering** — No one-line helpers, no deep abstraction for a single call site.
3. **Use existing conventions** — Read surrounding code; match naming, types, and layout.
4. **Comments** — Only for non-obvious business or performance constraints.
5. **Tests** — Add them when requested or when they cover real behavior; skip trivial assertions.

When the task is **question-only** or **review-only**, do not edit code unless asked.
